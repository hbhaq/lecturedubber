# Provider verification

Official documentation inspected 2026-10-15. This verifies documentation, not live account access or real mixed-language quality.

- [Speech-to-text guide](https://developers.openai.com/api/docs/guides/speech-to-text): recorded audio requests have a documented 25 MB limit. `whisper-1` supports `verbose_json` and segment/word timestamp granularities; the current adapter requests segment timestamps. Other transcription models cannot be substituted blindly because timestamp output contracts differ. Files are chunked below the limit; the app sets no separate full-lecture duration cap.
- [Whisper model](https://developers.openai.com/api/docs/models/whisper-1): multilingual recognition is the chosen baseline. The current guide does not establish a quality guarantee for Urdu–English code-switching. Urdu detection/term accuracy and segment timing remain an explicit sample and live acceptance requirement, not an assumed guarantee. Language is left automatic to avoid forcing the entire mixed lecture into one language. The short glossary prompt is limited conservatively by characters, not a precise 224-token tokenizer.
- [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini) and [structured output](https://developers.openai.com/api/docs/guides/structured-outputs): the LLM adapter uses the Responses API with a Pydantic schema. Refusals/missing parsed output fail visibly. Translation runs per utterance with course context/glossary, not one enormous lecture request. Notes use batches of 20 reviewed utterances to bound requests. Prompts prohibit inventing explanations, fixing math silently, and inferring unseen equations. These are behavioral instructions, not guarantees; human review is required.
- [Speech create API](https://developers.openai.com/api/reference/python/resources/audio/subresources/speech/methods/create) and [TTS guide](https://developers.openai.com/api/docs/guides/text-to-speech): `gpt-4o-mini-tts`, voices coral/alloy/sage, pronunciation instructions, and WAV are supported. Documented input maximum is 4096 characters; this app caps reviewed segments at 4000. Speech is disclosed as synthetic. No voice cloning is used.
- [API data controls](https://developers.openai.com/api/docs/guides/your-data): API data is not used for training by default. Retention depends on endpoint and account controls. The inspected table lists no abuse-monitoring/application-state retention for audio transcription and 30-day abuse monitoring for speech and Responses. Responses calls explicitly use `store=False`; this does not by itself enable Zero Data Retention. Verify your organization's actual retention eligibility/settings before sensitive processing. No Files API upload storage is used by this implementation.

## Data leaving your computer

Live STT sends extracted lecture audio and a short glossary. Translation sends the original segment, supplied context and glossary. TTS sends reviewed English and pronunciation guidance. Notes sends reviewed English, title/topic and segment IDs. Source screen video and screenshots are not sent to providers. Demo sends nothing to AI providers. API keys stay in backend environment variables, not frontend bundles, database or logs. Provider error bodies are not displayed for generic failures. The app stores lecture content on local disk/database until deletion.

## Pricing and replacement adapters

No current prices are hardcoded or estimated. The UI labels estimates unavailable, records returned usage and locally measured TTS input characters. Consult the official pricing page/account before a full lecture. API billing may include failed/interrupted accepted requests. Cached completed outputs avoid most repeated work; cache commits cannot be atomic with external billing.

`app/providers.py` defines independent `STT`, `Language`, and `Speech` protocols plus separate OpenAI implementations and demo implementations. Implement an adapter/factory change to replace a stage. Preserve source timestamps (or add a supported alignment step) for a different STT service. The current STT adapter intentionally rejects a non-Whisper model setting rather than claiming unsupported timestamps. Vision is deferred as described in README.

## Browser capture verification

The [MDN getDisplayMedia reference](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia) documents user activation/permission requirements and browser-dependent display audio. The [MediaRecorder reference](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder) documents pause/resume and MIME capability detection. Implementation uses `getDisplayMedia({video:true,audio:false})` plus a separate `getUserMedia({audio:...,video:false})`, checks the actual microphone track, combines those tracks explicitly and meters that microphone. This avoids assuming display capture includes microphone audio. Actual Chrome/Edge permission/capture testing is recorded separately in VALIDATION.md.
